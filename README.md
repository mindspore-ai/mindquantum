# Ascend DSB / BSB

在 Ascend 910B 上运行离散模拟分岔（DSB）和弹道模拟分岔（BSB），并行搜索 Ising 问题的低能量解。

Ising 问题的变量称为自旋，只取 −1 或 +1，其能量由耦合矩阵 `J` 和外场 `h` 决定。
模拟分岔先演化连续的位置与动量，再把位置转换为候选自旋，用能量比较候选解的好坏。
DSB 和 BSB 都是启发式算法，不保证找到全局最优解。

## 同一个问题，从许多初态出发

不同初态可能得到不同的候选解，因此同一个问题往往需要尝试许多初态。本实现把这些搜索组成一批，
称为 **batch**：每个副本有自己的位置与动量，所有副本共享 `J` 和 `h`。
这样，耦合计算可以交给 NPU 的矩阵乘单元，而不是为每个副本分别读取和计算整个问题。

这也决定了接口的用法：构造 `Solver` 时准备问题，调用 `run` 时更换初态。
同一 Solver 可以反复运行，复用已经上传的数据和设备执行图。主要优化对象是这种**固定问题、批量搜索、反复求解**的工作负载。

求解需要 Ascend 910B 系列 NPU 与 CANN 9.1，已在 910B2 上验证，不提供 CPU 回退。
设备端采用稠密矩阵计算，即使输入是 SciPy 稀疏矩阵，`J` 的内存需求仍按变量数的平方增长。
大而极稀疏的问题需要另行比较稀疏 CPU 实现的成本。

## 已测到的收益

在 910B2 上，以 FP32、100 个副本、1000 步运行，新版 DSB 在 QPLIB_3506 和 1024 变量稠密问题上的
重复求解分别比旧版快 14.3×、20.8×。比较包含状态传输，也包含复用问题数据带来的收益；构造 Solver 的成本另计。

精度默认采用 FP32。所测 QPLIB 实例中，HF32 的加速比中位数接近 1，却改变了部分搜索结果。
[性能报告](docs/benchmarks.md)给出了计时范围、CPU 对照、解质量和复现命令，可以据此判断这些收益是否适用于自己的任务。
